- [ ] Federation 1: authority logs (`FEDERATED.md` §6). Each identity, user or server, keeps an append-only BLAKE3 Merkle Mountain Range (MMR) of its authority changes: key rotations, addresses and certificates, owner changes and delegations. It also keeps a sparse Merkle tree of its current state. Chat messages never go in the log. The identity signs checkpoints: sequence, MMR size and root, state root, previous checkpoint, expiry. Batch changes into one checkpoint, because SLH-DSA signing is slow. The signed server record becomes the latest checkpoint, with one entry per address (IPv4, IPv6). - [ ] Federation 2: names (§4-5). An identity signs delegations "label → child root". Each has a scope: one name or a subtree, record types, whether it can delegate further, and expiry.
